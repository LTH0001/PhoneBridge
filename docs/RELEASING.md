# 发布前检查清单

## 已完成的源码准备

- [x] 自有代码选择 MIT；第三方声明独立保留。
- [x] 移除公开构建入口对旧工程目录的默认依赖。
- [x] 公开源码使用文件白名单，排除配置、令牌、模型、二进制、密钥和本机驱动恢复脚本。
- [x] 增加构建/依赖/架构文档、贡献与安全说明、CI 和源码扫描入口。

## 作者在公开前仍须确认

- [ ] 确认原始 Android/协议等代码的权利来源，确认有权以 MIT 发布；文件存在本机不代表版权已经明确。
- [ ] 人工检查导出的每个文件与图片，特别是第三方片段、个人信息和截图；基本扫描不是全面审计。
- [ ] 如考虑申请专利，先做相应评估，不先公开核心方案。
- [ ] 选择 GitHub 仓库名称、简介与作者显示信息；检查 Git 提交邮箱隐私。
- [ ] 在干净 Windows 和另一部手机上按 README 从头验证并记录结果。

## 二进制 Release 的额外条件

- [ ] 为第三方驱动、Python 原生组件、编解码库、模型补齐分发许可、NOTICE、对应源码及替换说明（如适用）。
- [ ] 使用有来源和构建记录的原生摄像头；不发布旧 Softcam DLL。
- [ ] 建立独立的 Android 正式签名、Windows 发布签名及版本升级流程，密钥不得入库。
- [ ] 实测 USB 授权、断线重连、副屏、摄像头、输入与撤销权限；AOA / 无线未完成的部分明确标为实验。
- [ ] 对最终发布产物重新生成清单与摘要；不能把以前的本机开发 ZIP 直接当正式成品。

## 推荐操作顺序

先运行测试与 `scripts/audit-source.py`，再运行 `scripts/package-source.py`。只检查/提交导出的干净源码目录，不上传整个工作目录，也不上传以前的 `dist/` 开发包。新源码目录没有 Git 历史；作者确认上述事项后再初始化/连接自己的仓库并推送。本项目整理脚本不执行 Git 提交或公开发布。
